# LINE CRM สะสมแต้ม (v2)

ระบบสะสมแต้มผ่าน LINE สำหรับร้านค้า **ใช้โค้ดชุดเดียวกับทุกร้าน** แต่ละร้านต่างกันแค่ไฟล์ตั้งค่าและชีตของร้าน

- **หน้าลูกค้า** (เปิดใน LINE): สมัครสมาชิก (ชื่อ นามสกุล วันเกิด วัน/เดือน/ปี พ.ศ. เบอร์โทร — บังคับทุกช่อง) + ยอมรับ PDPA · บัตรสมาชิก + QR · แลกของรางวัล · คูปอง (แสดง QR ให้พนักงาน) · ประวัติแต้ม
- **หน้าพนักงาน**: สแกน QR / ค้นเบอร์ → บันทึกยอดซื้อ (ระบบคิดแต้มเอง) · ใช้คูปอง · ปรับแต้ม (เฉพาะผู้จัดการ) · รายการล่าสุด
- **หลังบ้านเจ้าของร้าน** (คอมหรือมือถือ): ภาพรวม + กราฟ · สมาชิก (ค้นหา ดูรายคน ปรับแต้ม ระงับ) · รายการแต้ม · คูปอง · ของรางวัล · โปรโมชัน · พนักงาน · ตั้งค่าร้าน · ส่งออก CSV — ไม่ต้องเปิดหรือแชร์ Google Sheet
- **หลังบ้าน**: Google Apps Script + Google Sheets ของแต่ละร้าน

## โครงสร้าง

```
index.html          หน้าลูกค้า (ทุกร้านใช้ร่วมกัน)
staff.html          หน้าพนักงาน
admin.html          หลังบ้านเจ้าของร้าน (OWNER / ADMIN)
app/                โค้ดหน้าเว็บ (customer.js, staff.js, admin.js และส่วนที่ใช้ร่วมกัน)
themes/             base.css (โครง) + ธีมสำเร็จรูป luxury.css, minimal.css
shops/shops.js      รายชื่อร้าน + โดเมนของแต่ละร้าน
shops/<ร้าน>/       config.js (ชื่อ สี ธีม LIFF ID URL หลังบ้าน ข้อความ) + โลโก้/รูป
vercel.json         กฎลิงก์: /<ร้าน> → หน้าลูกค้า, /<ร้าน>/staff → หน้าพนักงาน, /<ร้าน>/admin → หลังบ้าน
code.gs             หลังบ้าน (วางใน Apps Script ของแต่ละร้าน — ไฟล์เดียวกันทุกร้าน)
tools/              เว็บทดสอบในเครื่อง + ชุดทดสอบอัตโนมัติ (ไม่ขึ้น Vercel)
```

ร้านถูกเลือกจาก **โดเมน** (เช่น `khamwan.com` ถ้าใส่ไว้ใน `shops/shops.js`) หรือจาก **ลิงก์** `/<ร้าน>` บนโดเมนหลัก

### ค่าของร้านอยู่ที่ไหน

| ค่า | อยู่ที่ | ใครแก้ |
|---|---|---|
| LIFF ID, URL หลังบ้าน (apiUrl), ฟอนต์ | `shops/<ร้าน>/config.js` | เรา |
| ชื่อร้าน โลโก้ สไตล์ สี ข้อความ นโยบายความเป็นส่วนตัว | หลังบ้าน เมนู **หน้าตาร้าน** (เก็บในชีต Settings) — ว่าง = ใช้ค่าใน `config.js` | เจ้าของร้าน |
| อัตราแต้ม แต้มต้อนรับ ยอดสูงสุดต่อบิล อายุคูปอง | ชีต **Settings** (แก้ในหลังบ้าน → ตั้งค่าร้าน) | เจ้าของร้าน |
| LIFF_ID รหัสนำหน้าสมาชิก ฉบับนโยบาย | ชีต **Settings** (หลังบ้านดูได้อย่างเดียว) | เรา |
| ของรางวัล โปรโมชัน | หลังบ้าน หรือชีต **Rewards** / **Promotions** | เจ้าของร้าน / ผู้จัดการ |
| พนักงานและสิทธิ์ | หลังบ้าน (เมนูพนักงาน) หรือชีต **Staff** | เจ้าของร้าน |

กฎแต้มต้องอยู่ในชีต ไม่อยู่ใน config เพราะ Apps Script ต้องเป็นคนคิดแต้มเอง (ค่าที่อยู่ในหน้าเว็บ ใครเปิดดูโค้ดก็แก้ได้)

## ทดสอบในเครื่อง

LIFF ใช้กับ localhost ไม่ได้ หน้าเว็บในเครื่องจึง **จำลองผู้ใช้ LINE**

### แบบง่าย: ข้อมูลตัวอย่าง (ไม่ต้องใช้ Google)
ดับเบิลคลิก `เปิดเว็บทดสอบ LINE CRM - ข้อมูลตัวอย่าง.command` → Chrome เปิดหน้าลูกค้าให้เอง · ปิด: กด `Ctrl + C` หรือปิดหน้าต่าง Terminal
- ข้อมูลตัวอย่างสร้างโดย `tools/demo-server.js` (6 สาขา สมาชิก 18 คน รายการย้อนหลัง 45 วัน แต้มพิเศษ ของขวัญวันเกิด) อยู่ในหน่วยความจำ ปิดแล้วหาย เปิดใหม่ได้ชุดเดิม
- ใช้ `code.gs` ในโฟลเดอร์นี้จริง → แก้ code.gs แล้วเห็นผลทันที
- ลิงก์หน้าพนักงาน / หลังบ้าน แสดงในหน้าต่าง Terminal · สลับผู้ใช้ที่ปุ่ม 🧪 ทดสอบ
- ต้องมี Node · ใช้พอร์ต 8002 (หน้าเว็บ) + 8102 (ข้อมูลตัวอย่าง — ชนกับ gas-server ของชุดทดสอบ e2e ปิดก่อนรันชุดทดสอบ)

### แบบต่อ Apps Script ทดสอบของเราเอง (ข้อมูลอยู่ในชีตจริง)
ดับเบิลคลิก `เปิดเว็บทดสอบ LINE CRM - ชีตทดลองจริง.command` (ใช้ apiUrl ใน config.js หรือ URL ที่วางในปุ่ม 🧪) · สองไฟล์เปิดสลับกันได้ ไฟล์ที่เปิดล่าสุดเป็นตัวกำหนดข้อมูลที่หน้าเว็บใช้
> ⚠️ ห้ามเปิดโหมดทดสอบในสคริปต์ที่เว็บจริงใช้อยู่ (ใครก็ปลอมเป็นเจ้าของร้านได้) — ใช้สคริปต์ทดสอบแยกต่างหาก

1. สร้าง Google Sheet ทดสอบ → ส่วนขยาย → Apps Script → วาง `code.gs`
2. รันฟังก์ชัน `testSetup` (ขอสิทธิ์ + สร้างชีต) แล้วรัน `enableTestMode`
   > ⚠️ `enableTestMode` ใช้กับสคริปต์ทดสอบเท่านั้น **ห้ามรันในสคริปต์ของร้านจริง**
3. Deploy → New deployment → Web app (Execute as: Me, Who has access: Anyone) → คัดลอก URL `/exec`
4. ดับเบิลคลิกไฟล์ชีตทดลองจริง → กดปุ่ม **🧪 ทดสอบ** มุมซ้ายล่าง → วาง URL → บันทึก (หรือใส่ใน `CUSTOM_API` ในไฟล์ จะได้ไม่ต้องวางทุกครั้ง)
5. สลับเป็น "พนักงานทดสอบ" ในแผงเดียวกัน แล้วเปิดหน้าพนักงาน → ในชีต Staff เปลี่ยน Status เป็น `ACTIVE`

ลิงก์ทดสอบ: `http://localhost:8002/khamwan` · `http://localhost:8002/khamwan/staff` · `http://localhost:8002/khamwan/admin` · `http://localhost:8002/demo`
(หลังบ้าน: ผู้ใช้จำลองต้องเป็น `OWNER` หรือ `ADMIN` ในชีต Staff)

## เพิ่มร้านใหม่ / แก้แพ็กเกจ (ระบบใหม่ — Supabase)
```bash
node tools/new-shop.js            # เมนู: 1 เพิ่มร้านใหม่ / 2 แก้แพ็กเกจร้านเดิม
node tools/new-shop.js edit demo  # แก้แพ็กเกจร้าน demo ตรงๆ
```
(หรือดับเบิลคลิก `เพิ่มร้านใหม่ - แก้แพ็กเกจ LINE CRM.command` ในเครื่องพี่)
- ถาม: รหัสร้าน ชื่อ รหัส LIFF ตัวย่อรหัสสมาชิก อัตราแต้ม สี สไตล์ โดเมน → เลือกแพ็กเกจตั้งต้น (1 เริ่มต้น / 2 มาตรฐาน / 3 หลายสาขา / 4 เลือกเอง) แล้วปรับทีละสวิตช์ได้
- สร้าง: `shops/<ร้าน>/config.js` · บรรทัดใน `shops/shops.js` · `db/shops/<ร้าน>.sql` (วางใน Supabase) · `db/shops/<ร้าน>-owner.sql` (อนุมัติเจ้าของร้านคนแรก)
- จบแล้วพิมพ์ขั้นตอนที่เหลือ (ตั้ง LIFF · ส่งขึ้น GitHub · อนุมัติเจ้าของร้าน · ลิงก์ของร้าน)
- แก้แพ็กเกจ: แก้เฉพาะส่วน `features` ในไฟล์ร้าน + เตือนตอนลดแพ็กเกจ / มีผลเมื่อส่งขึ้นเว็บแล้ว
- ระบบใหม่: ตัวกลางตรวจแพ็กเกจซ้ำทุกคำสั่ง (`api/_lib/features.js` อ่านไฟล์ร้านไฟล์เดียวกัน) → ปิดแพ็กเกจ = เรียกคำสั่งตรงๆ ก็ไม่ได้ (`NOT_IN_PACKAGE`) / ลืมเปิด → เปิดทีหลังด้วยสคริปต์นี้แล้วขึ้นเว็บใหม่ ข้อมูลไม่หาย
- ไม่เข้าฐานข้อมูลเอง (รหัสฐานข้อมูลอยู่ใน Vercel เท่านั้น) → วางไฟล์ SQL ใน Supabase SQL Editor เอง

## ตรวจแต้มสมาชิก (ระบบใหม่)
วาง `db/check_points.sql` ใน Supabase SQL Editor แล้วกด Run ได้ทุกเมื่อ (อ่านอย่างเดียว ไม่แก้ข้อมูล)
- ได้ร้านละ 1 แถว: ช่อง **แต้มไม่ตรง = 0** ทุกร้าน → ถูกต้อง
- มากกว่า 0 → ช่อง "รายชื่อที่ไม่ตรง" บอกรหัสสมาชิก (ไม่เกิน 20 คน) → ส่งให้ผู้ดูแลระบบ / อย่าแก้แต้มด้วย SQL เอง ให้ปรับผ่านหลังบ้าน

## ส่งข้อความตามกลุ่ม (ระบบใหม่ — หลังบ้านเมนู "ส่งข้อความ")
เจ้าของร้านเลือกกลุ่มลูกค้า → เห็นจำนวนคน → เขียนข้อความ + รูป → ส่งทดสอบหาตัวเอง → ส่งจริงผ่าน LINE OA ของร้าน
- ส่งเฉพาะลูกค้าที่ยินยอมรับข่าวสาร + สมัครผ่าน LINE + ไม่ถูกระงับ (ระบบกรองเอง) / ใช้โควตาข้อความของแพ็กเกจ LINE OA ร้าน
- **รูปส่งเป็นริชเมสเสจ** (เต็มความกว้างแชต): เลือกรูปเดียว หน้าเว็บย่อเป็น 5 ขนาดให้เอง / แนะนำ 1040 × 1040 px ใช้ได้ตั้งแต่แนวนอน 2:1 ถึงแนวตั้ง 2:3 (ไม่ตัดรูปให้) / แตะรูปแล้วเปิดลิงก์ที่ร้านใส่ (ว่าง = บัตรสมาชิกของร้าน) / ลูกค้าแตะเพื่อขยายรูปไม่ได้
- **เพื่อน LINE OA (ตั้งค่าร้านในหลังบ้าน):** บังคับเพิ่มเพื่อนก่อนสมัคร (ค่าเริ่มต้นเปิด — สแกน QR สาขา → เพิ่มเพื่อน → สมัคร สาขายังบันทึกถูก) / ติ๊กช่องรับข่าวสารไว้ให้ (ค่าเริ่มต้นเปิด) / แต้มรับข่าวสาร ครั้งเดียวต่อคน (0 = ไม่ให้) — หน้าส่งข้อความบอก "ได้รับจริง" กี่คน (สถานะเพื่อนจดตอนลูกค้าเปิดบัตร ไม่ต้องตั้งค่าใน LINE เพิ่ม)
- เปิดใช้: สวิตช์แพ็กเกจ `broadcast` + ตาราง `db/005_broadcasts.sql`, `db/006_broadcast_rich.sql`, `db/007_oa_friend_consent.sql` (วางใน Supabase ครั้งเดียว ตามลำดับ) + รหัส OA ของร้านใน Vercel
- **เชื่อม LINE OA ของร้าน:** OA ต้องอยู่ **Provider เดียวกับช่อง LIFF ของร้าน** (ไม่งั้น LINE ID ที่เก็บไว้ใช้ส่งไม่ได้ และย้ายทีหลังไม่ได้)
  → LINE OA Manager เปิด Messaging API → LINE Developers ออก Channel access token (long-lived)
  → Vercel → เมนู Environment Variables (หรือ Settings → Environments → กดชื่อ Preview / Production): `LINE_OA_TOKEN_<รหัสร้านตัวใหญ่>` เช่น `LINE_OA_TOKEN_DEMO` (Preview = ลิงก์ทดสอบ / Production = เว็บจริง)
  → **Redeploy ให้ถูกตัว:** แท็บ Deployments → อันล่าสุดของ branch นั้น (`dev` = ลิงก์ทดสอบ) → ⋯ → Redeploy (กดอันบนสุดที่เป็น Production = ลิงก์ทดสอบไม่ได้ค่าใหม่)
  → เช็ก: หน้าส่งข้อความขึ้นชื่อ OA + โควตา / เจ้าของร้านที่เพิ่ม OA เป็นเพื่อนแล้วกด "ส่งทดสอบหาตัวเอง" ได้
- ลองในเครื่อง: `node tools/api-server.js` มี LINE OA จำลองให้ร้าน demo (ไม่ส่งจริง) ดูสิ่งที่ "ส่ง" ไปที่ http://localhost:8105/__oa

## สิทธิ์ลูกค้าตาม PDPA (ระบบใหม่)
- **ลบบัญชีสมาชิก:** ลูกค้าลบเองที่ "แก้ไขข้อมูล" → ลิงก์ล่างสุด (ยืนยัน 2 ชั้น พิมพ์ "ลบ") / เจ้าของร้านลบให้ที่หลังบ้าน → หน้าสมาชิก → "ลบข้อมูลสมาชิก" (ต้องใส่เหตุผล ห้ามใส่ชื่อ/เบอร์)
  - ลบจริง: ชื่อ เบอร์ วันเกิด รูป LINE ID หมายเหตุ / แต้มเป็น 0 (รายการ "ลบบัญชี") / คูปองที่ยังไม่ใช้ถูกยกเลิก / คำตอบที่จำไว้กันกดซ้ำที่มีข้อมูลคนนี้ถูกลบ
  - เหลือ: "สมาชิกที่ลบแล้ว" + รหัสสมาชิก + ประวัติยอดซื้อไม่มีชื่อ (ยอดขายร้านไม่เพี้ยน) + รหัสแปลงของ LINE ID (กันรับแต้มรับข่าวสารซ้ำ)
  - ไม่อยู่ใน: รายชื่อหลังบ้าน / การค้นของพนักงาน / ส่งข้อความ / Excel / จำนวนสมาชิก — LINE + เบอร์เดิมสมัครใหม่ได้ เริ่มจาก 0
- **ยอมรับนโยบายฉบับใหม่:** เจ้าของร้านแก้นโยบายในหน้าตาร้าน → ลูกค้าเดิมเปิดบัตรแล้วเจอหน้า "ร้านปรับปรุงนโยบาย" ต้องกด "ยอมรับ" ก่อน (แลกของ/รับของขวัญไม่ได้จนกว่าจะยอมรับ / ปิดรับข่าวสารและพนักงานบันทึกยอดได้ตามปกติ) / หน้าตาร้านบอก "ยอมรับฉบับล่าสุดแล้ว X จาก Y คน"
- เปิดใช้: วาง `db/008_member_delete_policy.sql` ใน Supabase ครั้งเดียว (ก่อนส่งโค้ดขึ้นเว็บ)

### ร้านที่มีหลายสาขา (code.gs 2.6.0)
ร้านสาขาเดียวไม่ต้องทำอะไร — ถ้ายังไม่เพิ่มสาขา ระบบซ่อนเรื่องสาขาทั้งหมด

**แพ็กเกจ (เราเป็นคนเปิดให้ร้านที่ซื้อแพ็กเกจหลายสาขา)** — ใน `shops/<ร้าน>/config.js`:
```js
features: { branches: true, maxBranches: 6 }   // ไม่ใส่ maxBranches = ไม่จำกัด / branches: false หรือไม่ใส่ = แพ็กเกจพื้นฐาน
```
- ตั้งในไฟล์บน Vercel เพราะเจ้าของร้านแก้เองไม่ได้ (ชีต Settings อยู่ในบัญชีร้าน แก้ได้)
- ปิดแพ็กเกจ = ไม่มีเมนูสาขา (เพิ่ม/แก้สาขาไม่ได้) แต่ข้อมูลสาขาเดิมไม่หาย / เพดานนับเฉพาะสาขาที่เปิดอยู่
- ข้อจำกัด (ระบบเดิม Apps Script เท่านั้น): ร้านที่รู้วิธีพิมพ์เพิ่มสาขาในชีตเองยังทำได้ (ชีตอยู่ในบัญชีร้าน) — คุมด้วยสัญญาการใช้งาน / ระบบใหม่ตัวกลางตรวจเพดานสาขาเองแล้ว

1. หลังบ้าน → เมนู **สาขา** → เพิ่มสาขา (เจ้าของร้าน)
2. เมนู **พนักงาน** → แก้ไขแต่ละคน → ติ๊กสาขาที่ทำงานได้ (หรือ "ทุกสาขา") — พนักงานเดิมที่ยังไม่ได้ตั้ง = ทุกสาขา
3. เมนู **สาขา** → **QR สมัคร** → บันทึกเป็นรูป แล้วพิมพ์ติดเคาน์เตอร์ของแต่ละสาขา (ลิงก์ `https://liff.line.me/<LIFF ID>?branch=B001`)

ระบบรู้สาขาจาก:
- ยอดซื้อ / ใช้คูปอง / ปรับแต้มที่หน้าร้าน → สาขาที่พนักงานเลือกไว้ (อยู่สาขาเดียว = เลือกให้เอง / หลายสาขา = เลือกตอนเปิดหน้าพนักงาน เครื่องจำไว้) — Apps Script ตรวจว่าคนนั้นอยู่สาขานั้นจริง
- สมาชิกใหม่ → QR ของสาขาที่สแกน (ไม่ได้สแกน / สาขาปิดแล้ว = `ONLINE`)
- ปรับแต้มจากหลังบ้าน → `ADMIN`
- แต้มใช้ร่วมกันทุกสาขา · ไม่มีปุ่มลบสาขา (รายการเก่าอ้างถึงอยู่) ใช้ "ปิดสาขา" แทน
- ชีตใหม่ `Branches` + คอลัมน์ท้ายชีต `Branch` (Transactions) `Used_Branch` (Coupons) `Joined_Branch` (Members) `Branches` (Staff) — ระบบเติมให้เองตอนใช้ครั้งแรก
- ความเร็ว: Apps Script บันทึกได้ทีละรายการทั้งร้าน (~1–2 วินาที/รายการ) — 6 สาขายังไหว ถ้าเกิน ~10 สาขาที่คนแน่นพร้อมกัน ควรย้ายไปฐานข้อมูลจริง

รูปของรางวัล/โปรโมชัน:
- กด **อัปโหลดรูป** ในหลังบ้าน → ย่อรูปในเครื่อง (ด้านยาว ≤ 1200px, ≤ 2MB) → เก็บใน Google Drive ของบัญชีเจ้าของ Apps Script และแชร์ "ทุกคนที่มีลิงก์" ให้เอง
- โฟลเดอร์: ค่า `IMAGE_FOLDER_ID` ในชีต Settings (วางลิงก์โฟลเดอร์ได้ บัญชีเจ้าของ Apps Script ต้องเป็น "ผู้แก้ไข") / ว่าง = สร้างโฟลเดอร์ "LINE CRM - รูปร้าน" ให้เอง
- หรือวางลิงก์รูป / ลิงก์แชร์ Google Drive เองก็ได้ ระบบแปลงเป็นลิงก์รูปให้
- [ ] ร้านต้องใส่นโยบายความเป็นส่วนตัวของจริงใน config (`legal`) — ข้อความในตัวอย่างเป็นแค่แม่แบบ

- ผู้ใช้เจอ "กรุณาติดต่อผู้ดูแลระบบ" → ดูสาเหตุจริงใน Apps Script เมนู **การดำเนินการ (Executions)** (ข้อความบนหน้าเว็บตั้งใจไม่บอกว่าข้อมูลเก็บที่ไหน)
- ความเร็ว: Apps Script จำค่าร้าน/ของรางวัล/โปรโมชันไว้ 5 นาที แก้ผ่านหลังบ้านหรือพิมพ์แก้ในชีตเห็นผลทันที (onEdit) ถ้าวางข้อมูลด้วยวิธีอื่นแล้วไม่เปลี่ยน กด Run `clearCache`
- หน้าเว็บกับ code.gs ต้องขึ้นคู่กัน: หน้าเว็บใหม่ + code.gs เก่า → หลังบ้านขึ้น "ไม่รู้จักคำสั่งนี้"
- **2.6.0 (หลายสาขา):** ขึ้นหน้าเว็บก่อน แล้ววาง code.gs + New version → **ค่อยเพิ่มสาขาหลังจากทั้งสองอย่างขึ้นแล้ว** (หน้าพนักงานรุ่นเก่าไม่ส่งสาขา ถ้ามีสาขาแล้วจะบันทึกไม่ได้)

## เพิ่มโดเมนให้ร้าน
1. เพิ่มโดเมนในโปรเจค Vercel + ตั้ง DNS
2. ใส่โดเมนใน `shops/shops.js` → `domains: ['khamwan.com']`
3. เปลี่ยน Endpoint URL ของ LIFF เป็น `https://khamwan.com`

ลิงก์ `liff.line.me/...` ใน Rich menu ไม่ต้องเปลี่ยน

## ยังไม่ได้ทำ (ตามแผน)
- ลบของรางวัล/โปรโมชัน (ตอนนี้ใช้ "ปิด" แทน) · อัปโหลดรูปจากเครื่องตรงๆ (ตอนนี้ใช้ลิงก์)
- ระดับสมาชิก · แต้มหมดอายุ · สิทธิ์วันเกิด · แนะนำเพื่อน · ส่งข้อความ LINE
- ชีต Transactions ใหญ่มาก (หลายหมื่นแถว) จะเริ่มช้า (หน้าพนักงานและหลังบ้าน) → ย้ายข้อมูลปีเก่าไปชีตเก็บถาวร
